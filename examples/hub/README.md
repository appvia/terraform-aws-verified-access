# Hub and spoke example

A hub VPC holding the Verified Access endpoints and the central load balancer, a spoke VPC holding two private SSH hosts, and a transit gateway between them. The module is called with `topology = "hub"`: each endpoint's `targets` become an IP target group behind a listener on the central load balancer, so engineers reach the hosts in the spoke with the Connectivity Client. Alarms (to a new SNS topic) and a CloudWatch dashboard are switched on; a module requested certificate for http endpoints and Route 53 records (`dns`) are shown commented out.

Both hosts listen on port 22, so each endpoint sets its own `listener_port` (2201 and 2202) on the central load balancer. The listener port is also the port users connect to, for example `ssh -p 2201 ec2-user@<target-a-ssh endpoint domain>`; the load balancer forwards to port 22 on the host.

The targets' addresses are fixed so that they are known at plan time, as load balancer targets must be.
